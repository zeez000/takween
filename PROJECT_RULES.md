# Takween project rules and blueprint scope

Authority: owner-supplied 3d website blueprint.docx, read 3 November 2026.
The owner has explicitly adopted it as the project brief and working rules.
The earlier matching Word blueprint is reference; the unrelated PDF is excluded.

## Owner decisions take precedence

- Brand is TAKWEEN, confirmed by the owner after the blueprint was written.
  References in the document to a temporary name are superseded.
- Tagline: YOU NAME IT. WE MAKE IT.
- Preserve existing working homepage sections, services, quotation draft,
  navigation and Fateen Technologies content. Extend the existing Next.js app.
- Current milestone is the original procedural mechanical sculpture and
  deterministic reversible scroll-controlled explosion, then entry/typography,
  accessibility, optimisation and testing. Finish before unrelated features.
- Never invent customer information, testimonials, completed projects, real
  prices or confirmed printer/manufacturing capabilities.
- No public deployment, domain registration, purchases or paid services without
  explicit owner approval. Blueprint launch suggestions do not grant that approval.

## Experience rules

Premium black/graphite, crimson and metallic visual story. Original geometry or
verified licensed assets. Coordinate effects, keep sculpture central, support
native scrolling. Exact timeline follows the owner's cinematic milestone:
0-20% assembled; 20-65% explode; 65-85% inspect; 85-100% reassemble.
Same progress gives same transforms in either scroll direction.
Allow assembled-view drag/touch rotation, reset and bounded zoom without fighting
scroll control. Vertical touch scrolling must remain usable.
Entry must be lightweight, skippable, optional on repeats and bypassed for hashes,
internal routes and reduced motion. No invented loading percentages or delays.
Use lazy scenes, limited DPR, shared geometry, instanced repetition, on-demand
rendering, visibility/background pausing, proper disposal and WebGL fallbacks.
Keep essential content and controls accessible; verify desktop and mobile.

## Broader blueprint remains planned until built

Three enquiry paths (model, idea, sample); secure uploads and unique confirmed
request IDs; 20-30 approved original/licensed sample designs and conventional
accessible grid; grand finale; phone-friendly secure admin; manual quotations;
cost calculation and PDF quotes; production, stock, payments and reporting.
Do not show fake successful submissions, counters, financial data or availability.
Supabase auth, RLS, private storage, server validation/rate limiting, retention,
backup and payment verification need implementation and tests before live use.
The blueprint is not evidence that any of these features already work.

## Verification and reporting

Inspect before edits. Run lint, TypeScript, production build and relevant tests.
Test forward/reverse scroll, drag, reset, mobile gestures, WebGL failure, reduced
motion, entry bypass and existing navigation/quotation regressions.
Report actual test outcomes, remaining work and performance evidence honestly.
Do not claim real-device 60 FPS or Lighthouse targets without measurements.
